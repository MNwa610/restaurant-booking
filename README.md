# Система бронирования столиков

## Назначение

Приложение для учёта столиков ресторана и управления бронированиями.
Консольная версия (ПР3) дополнена веб-интерфейсом на Django (ПР5).

Приложение позволяет:

* просматривать столики в браузере;
* просматривать информацию о конкретном столике;
* просматривать список бронирований в браузере;
* просматривать информацию о конкретном бронировании;
* проверять доступность столика на текущую дату;
* искать столики по расположению;
* проверять вместимость столиков;
* создавать бронирования;
* отменять бронирования;
* хранить данные между запусками приложения.

## Используемые технологии

* Python 3;
* Django 5.2 – веб-фреймворк;
* HTML – разметка веб-страниц;
* CSS и Bootstrap 5.3 – оформление страниц;
* pytest – автоматизированные тесты;
* flake8 – проверка качества кода.

## Целевая аудитория

Администраторы и сотрудники ресторана, которым нужно учитывать столики
и бронирования гостей.

## Предметная область

Основными объектами предметной области являются:

* столик;
* пользователь;
* бронирование.

Пользователь может создавать бронирования столиков на определённые даты.
Один столик не может иметь два активных бронирования на одну и ту же дату.
Отменённое бронирование не блокирует столик.

## Основные сущности

### Table – столик

Объект `Table` представляет столик, доступный для бронирования.

Основные атрибуты:

* `number` – номер столика;
* `capacity` – вместимость;
* `location` – расположение в зале.

Основные методы:

* `is_suitable_for()` – проверка соответствия числу гостей;
* `validate_capacity()` – проверка допустимой вместимости;
* `__str__()` – строковое представление.

### User – пользователь

Объект `User` представляет пользователя системы.

Основные атрибуты:

* `id` – уникальный идентификатор;
* `name` – имя;
* `email` – адрес электронной почты.

Основные методы:

* `from_data()` – создание объекта из данных JSON;
* `__str__()` – строковое представление.

### Booking – бронирование

Объект `Booking` представляет бронирование столика пользователем.

Основные атрибуты:

* `id` – уникальный идентификатор;
* `table` – объект `Table`;
* `booking_date` – дата бронирования;
* `user` – объект `User`;
* `is_cancelled` – признак отмены.

Основные методы:

* `cancel()` – отмена бронирования;
* `__str__()` – строковое представление.

## Страницы веб-интерфейса

* `/` – главная страница: описание приложения и навигация
  (view-функция `index()`);
* `/tables/` – список столиков: объекты `Table` из `data/tables.json`
  (view-функция `tables()`);
* `/tables/<int:table_number>/` – страница столика
  (view-функция `table_detail()`);
* `/bookings/` – список бронирований: объекты `Booking`
  из `data/bookings.json` (view-функция `bookings()`);
* `/bookings/<int:booking_id>/` – страница бронирования
  (view-функция `booking_detail()`).

Если столик или бронирование с указанным идентификатором не найдены,
страница возвращает код статуса 404. Для неизвестного URL настроена
собственная страница ошибки (`handler404`).

## Основные операции

### Используется в веб-интерфейсе (ПР5)

* просмотр списка столиков;
* просмотр информации о столике;
* просмотр списка бронирований;
* просмотр информации о бронировании;
* проверка доступности столика на текущую дату.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консольной версии.
В веб-интерфейсе они появятся после добавления форм и POST-запросов:

* поиск столика по расположению;
* проверка вместимости;
* фильтрация и сортировка столиков;
* создание бронирования;
* отмена бронирования;
* создание пользователя.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

* `data/tables.json`;
* `data/users.json`;
* `data/bookings.json`.

При загрузке данные из JSON преобразуются в объекты `Table`, `User`
и `Booking`. Для связи бронирования со столиком и пользователем
в `bookings.json` используются `table_number` и `user_id`.

## Назначение модулей

### `main.py`

Консольная версия приложения (сохранена с ПР3).

### `restaurant_booking/`

Пакет настроек Django-проекта:

* `settings.py` – настройки проекта;
* `urls.py` – маршрутизация верхнего уровня;
* `asgi.py`, `wsgi.py` – точки взаимодействия с сервером.

### `homepage/`

Django-приложение главной страницы:

* `views.py` – функция `page()` (общий HTML-каркас) и `index()`;
* `urls.py` – маршрут главной страницы.

### `tables/`

Django-приложение столиков:

* `views.py` – `tables()` и `table_detail()`;
* `urls.py` – маршруты приложения.

### `bookings/`

Django-приложение бронирований:

* `views.py` – `bookings()` и `booking_detail()`;
* `urls.py` – маршруты приложения.

### `models/`

Классы предметной области ПР3: `Table`, `User`, `Booking`.

### `storage.py`

Загрузка и сохранение JSON: преобразование JSON ↔ объекты Python.

### `utils.py`

Вспомогательные функции консольного ввода.

### `tests/`

Автоматизированные тесты проекта.
